Paints picker — four directions and a recommendation

The problem (Ryan, 2026-10-27): the Studio’s ☰ Paints drawer is “redundant and confusing for users”. On a 390px phone, the seed toolbar is 3 rows (178px). The open drawer adds 4 rows of controls (194px) and shows only about 3½ paints. Most of its controls exist somewhere else too.

An audit read the code and the docs. Four agents each designed one direction, and three judges scored them: the painter, the constitution and accessibility, and the build. All three judges chose the same base. The recommended mix is at the end, and you can try it: it runs on 134 real paints from all ten brands, with the app’s own ΔE 2000 code.

Today

One job (choose the colour that starts the scheme) has two text inputs. One drawer copies the Shelf’s filters and its import and export. The first phone screen is all controls.

Bugs found on the way (reproduced)

  • Small phones open scrolled down. At 360px and 375px wide, the page loads part of the way down. The offset depends on the viewport height, for example 401px at 360×640, 384px at 375×667 and 239px at 375×812. The cause is syncTabs() in app.js: its scrollIntoView on the active tab also scrolls the page. At 390px wide the tabs fit, so the page does not move.
  • A tap on ☰ Paints raises the keyboard. It always focuses the search, so the keyboard covers the paints.
  • A pasted #9A1115 does nothing. The hex box keeps 6 characters, so it holds 9A111.
  • A paint name in the hex box makes a colour. “Abaddon Black” seeds #ABADDB.
  • Marks do not always refresh. After a mark, the hero, the drawer or the Studio can show the old state, until the next full render. With Use my collection on, even the matches can be stale.
  • The drawer is heavy. It holds 3,225 buttons (3,232 tab stops). It rebuilds all of them on every seed change (paint, hex, photo, undo), also while it is closed. A wheel drag does not rebuild it.
  • After a wheel drag, the drawer is out of date. It still rings the old paint and marks it aria-selected. “Closest to base” keeps the old order.

Recommended: one seed field, and a list that only picks Recommended

It uses the structure of A and adds the best parts of C and D. One field takes a paint name, a brand word or a hex. Browse (▾ on desktop, a grid button on a phone) opens a colour grid without the keyboard. A tap only picks a paint. Marking moves to a long-press menu. Import and export leave the Studio. The brand and type filters stay on the Shelf.

Choices for you (the judges disagreed)

  • Live hex. Today a hex seeds as you type. The proposal keeps that for # + 6 digits. It asks for Enter for anything else (a bare 9A1115, or #9A1). The accessibility judge wanted Enter for everything: “nothing seeds while typing” was that judge’s must-have. On a phone, the open list and the keyboard cover the scheme, so you do not see the live change until the list closes. Each live edit also adds one undo step. If live hex stays, the polite live region says the new seed, and Esc puts back the seed from before you typed. This page does both.
  • #RGB live. Two judges (the painter and the build) wanted #RGB to seed live too. The proposal says no. When you type #9A1115, the first 3 digits would seed #99AA11 for a moment.
  • Marking in the Studio. The proposal uses a long-press menu (no new buttons). Two judges preferred a small “✓ own · + buy” pair on each Plan row. That pair is easier to find, but it adds more small buttons, and today’s buy buttons are already under 44px.
  • Recent picks. The proposal keeps them for this visit only, so they are not new saved data and need no backup or delete. One judge wanted them saved. The build judge wanted to leave Recent out of this change.
  • Filters in the picker. The painter wanted a Filters sheet in the picker, with a new title. The proposal uses brand and type words in the field instead.
  • Browse grid or rows. The proposal uses a grid to browse (you look by colour) and rows to search (you read names). The grid uses the APG grid pattern: rows and cells, so a screen reader says the row and the column, and the arrow keys move in two directions. The other option is rows everywhere. The accessibility judge specified rows.

Fixed by this change

  • The keyboard rises only when you tap the field, never on Browse.
  • A pasted #9A1115 works, and “Abaddon Black” can never become #ABADDB.
  • The list exists only while it is open: one tab stop instead of 3,232. It is built when it opens, from the current pick, so a wheel drag cannot leave it out of date. There is no rebuild of 3,225 buttons on each seed change.
  • One render('marks') path: a mark anywhere updates the hero, the palette, the open list and the Shelf.
  • The small-phone load scroll (syncTabs() in app.js, the scrollIntoView on the active tab). You can also fix it now, on its own.
