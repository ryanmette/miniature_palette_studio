“Use my paints” and the ⋯ menu

Part 2 (2026-10-27): the full ⋯ menu, from a menu audit, is the last section on this page.

The question: should Use my collection (Off · Prefer owned · Only owned) move from the Plan tab to the global ⋯ settings menu? Short answer: yes, with one condition — the live palette must say when the setting is on, because it changes the paints you see there.

What the setting does today (matchOpts() in app.js): Prefer owned ranks each owned paint as if it were ΔE 6 closer (OWNED_BOOST; the ΔE you see stays true). Only owned keeps only owned paints in the search. It ranks the live palette, the Plan and the Accessibility swap. It does not change Equivalents. It is saved on your device (store.setPref('collection')), and a share link does not carry it. But its only control is in the Plan tab, two screens below the palette on a phone.

Paint names and ΔE values in the frames come from the real dataset: the target colours are the Alga Green scheme (#555E1B · #241B5E · #C8A13A), and the example shelf holds 23 common Citadel paints, with no dark blue or purple. I read every value from the running app with that shelf, so the frames show what the app really does in each state.

Why these choices

  • Why below the palette, not next to its label. I put a chip after “Live palette → nearest paint” in the real app and measured it. At 1280px it pushed undo, redo, + and Ideal|Real down to a second row (header height 36 → 74px). On a phone it needed its own row anyway. Below the palette, it fits on one line at every width, and it sits right under the paint names it explains.
  • Why a full-width button, not a small pill. It is a control as well as a status, so it must be 44px tall on touch (§3.6). On desktop it uses the normal 38px --tap.
  • Contrast. The usual badge pair, --success text on --success-weak, is only 3.0:1 in the light theme. That fails WCAG AA for 12px text. So the note’s text uses --text on --surface (14:1). Only the ✓ glyph is green: 3.3:1 light and 6.3:1 dark, which passes the 3:1 limit for graphics.
  • No jiggle (§3.4). The note appears only after you change a setting, never on hover or select, and it can only push content down. Changing the setting already redraws the paints, so the page does not move in a surprising way.
  • Keyboard and screen readers. The note is a <button aria-haspopup aria-controls="settingsMenu"> with an accessible name such as “Use my paints: prefer owned. Change”. Opening ⋯ from it moves focus to the selected option, and Esc returns focus to the note, not to ⋯. A change is announced through the existing live region. In the empty-shelf state the note opens the Shelf instead, so it drops aria-haspopup and its name says so: “Use my paints: prefer owned, but you own no paints yet. Open Shelf”.
  • Nothing else changes. The setting is still saved per device. A share link still does not carry it, so a friend who opens your link sees matches from their shelf. That is correct.
  • Constitution change (§3.6). The draft wording is in the full ⋯ menu section. It also removes “the Use my collection control lives in the Plan tab”.

Verdict: one setting, in one place, next to the other personal settings, plus an honest sign where its effect shows. Off costs nothing. On tells you why a paint you own beat a closer one.

B · The control lives on the palette, and ⋯ does not have it

The Off · Prefer · Only control sits below the live palette all the time, in place of the note.

Pro: one tap, and you see it where it acts. Con: a row of 44px controls stays in the studio forever, also for the many people who own nothing. It also looks like a per-scheme choice, but it is a saved preference that changes more than one stage, so no stage owns it.

C · Only in ⋯, with no sign on the palette

The same ⋯ row as A, but without the note.

Pro: the cleanest studio. Con: you turn on Only owned once, forget it, and a month later your accent is “Loose” and nothing says why. That breaks principle 4, “Explain, don’t mystify”, and principle 2, “Honest about approximation”. Not recommended.

Decisions (Ryan, 2026-10-26)

  • Direction A is chosen: the setting moves to ⋯, and the matching note shows on the live palette when it is on.
  • The label is “Use my paints” (Off · Prefer · Only). It is short enough for a phone. “Use my shelf” was not chosen, because the shelf also holds to-buy paints.
  • Equivalents ignores the setting. It compares brands, so it must list every brand. Owned paints already show ✓ in that list.
  • Empty shelf: the note says “Open Shelf” and opens the Shelf. In every other state it says “Change” and opens ⋯.

The full ⋯ menu Proposal · from the menu audit

Ryan asked if other things belong in ⋯. An audit read the code and the docs. It also read primary sources: Apple HIG, the Android design guide, MDN and WCAG. It judged each candidate from three views: the constitution, the painter and the platform. All three views agree on this shape: two new rows and one new button. First, fix the menu container. Other items stay where they are, move into About & data, or wait for a later release. A second review then checked this mockup against the code. Its corrections are in the lists below.

More

On desktop there is no Done button. Esc, a click outside, or ⋯ closes the menu.

Fix the container first (problems in the menu today)

  • It says “menu”, but it is not one. The panel is role="menu" and ⋯ says aria-haspopup="menu" (index.html), but it holds a switch, segmented groups and buttons. A screen reader then expects a list of commands that you move through with the arrow keys. It becomes a non-modal dialog named “Settings”, with aria-haspopup="dialog".
  • Focus has no rules. When the menu opens, focus moves into it. When it closes, focus returns to the control that opened it: ⋯, or the matching note. When an action closes the menu (Export list, Share link), focus returns to ⋯. When About & data closes, focus returns to ⋯. On a phone, a Done button closes it, because a phone has no Esc key.
  • Touch targets are too small. Export list, Share link and About & data are 32px (.btn.sm). The Language buttons are 30px (34px on a phone). The theme switch is 30px tall. Every control gets min-height: var(--tap), and the switch gets a 44px button around it. Note: --tap is 44px only at ≤520px, so an iPad gets 38px (see the open questions).
  • The focus ring cannot be seen. --focus is a 3px ring in --accent-weak: about 1.1:1 against the surface in both themes. WCAG 1.4.11 needs 3:1. This is an app-wide problem, with its own suggested task. The menu uses the fixed ring.
  • It cannot scroll. .popover has no height limit, so a taller menu runs off a short screen. The menu gets a max-height at every width and scrolls inside itself.
  • Wrong shadow, radius and padding. It uses --shadow (in-page). §3.4 gives floating overlays --shadow-pop. It is a panel of grouped controls, like About and the Filters sheet, so its radius becomes --r-card and its padding 16px (§3.5).
  • Labels are not localised. Theme, Language, Scheme, More and the button labels have no data-i18n. Every row, old and new, gets one (§4 i18n).
  • A backup can replace your shelf without a question. Today, Import… (Shelf and Paints drawer) also accepts a .json backup and replaces the shelf and settings at once. After the build there is one rule: every .json backup, from Restore… or from Import…, goes through the same confirm step.

Notes for the build

  • Back up downloads store.exportJSON() as palette-studio-backup-YYYY-MM-DD.json. The file gets a saved date, so the confirm can show it. A backup without that date shows no date.
  • Restore reads the file with a new store.inspectJSON(). It checks the shape and counts the paints, but does not apply anything. The confirm shows the counts. store.importJSON() runs only after Replace.
  • The settings in a backup are theme, language, Use my paints, tone ladder and Include Contrast. Remove the fill key from PREF_DEFAULTS: the app never reads it (Ideal | Real lives in the link).
  • A restored theme or language of “none” means “follow the device”. Apply it at once, without saving it.
  • Delete goes through a new store.clear(). It removes ps-state, the old ps-owned and ps-theme keys, and the iOS copy of the data. If only ps-state is removed, the next start brings the data back. Update privacy.html and support.html in the same change.
  • The version line reads the app version from one constant in src/. check-docs.mjs fails when it does not match package.json. The data version comes from paints.json.
  • Build with the real components (.seg, .btn, .btn.primary, .themesw). Add a --scrim token (the About backdrop value) for the confirm, About and the Shelf sheet. Add a §3.5 line for the destructive button: a secondary button, 1px --danger border, label in --text, ⚠ hidden from screen readers.
  • The hint changes only when you change Use my paints or open the menu, never on a store update. So marking paints on the Shelf does not make a screen reader repeat it. “Open Shelf” is outside the live region.
  • Undo on the Shelf. Today Ctrl/⌘ Z also works on the Shelf, where it changes the Studio palette that you cannot see. Make it work only in the Studio.

The rule, and the §3.6 change

  • Which settings go to ⋯. A setting moves to ⋯ when it is saved for the device, changes more than one stage, and changes the matches in a way that you cannot see. Use my paints meets all three. Include Contrast only adds a paint type, and each Contrast paint shows its finish icon, so you can see it. It stays in the Plan.
  • Draft wording for §3.6 (it goes in the same commit as the build): “The header holds only the Studio / Shelf switch and a ⋯ settings dialog (non-modal, not a menu) in three groups. This device: theme; language; Use my paints (off · prefer · only), a saved preference that ranks the live palette, the Plan, the Export list and the Accessibility swap, never Equivalents. The live palette shows the matching note while it is on. Actions: Export list / Share link, the whole-scheme output actions; Back up / Restore…, the whole-device backup of the store.js state (Restore confirms before it replaces). Information: About & data, and Help (support.html). Delete your data, keyboard shortcuts and the version live in About & data. Don’t move per-scheme or in-stage controls into the header. The only header actions are the whole-scheme Export/Share and the whole-device Back up/Restore.” Also add the settings dialog and the confirm to the --shadow-pop list in §3.4.

Open questions for you

  • Help in ⋯. Two views want a Help button next to About & data. The third view measured the old menu: two new buttons (Privacy and Help) made it too wide for a 360px screen. With the new phone layout, one Help button fits. Keep it?
  • Contrast in the matching note. Must the note under the palette also show when Include Contrast is on (for example “Contrast paints included”), not only when Use my paints is on?
  • A way back to “follow the phone”. After today’s fix, the app follows the phone until you tap the theme switch. Then it keeps your choice, and no control lets you follow the phone again (only Delete your data). Add one, for example a “Use phone setting” link under the switch that shows only when you have picked a theme?
  • 44px on every touch screen. --tap is 44px only at ≤520px, so an iPad or a phone turned sideways gets 38px. Change it to apply on every touch screen (pointer: coarse)? This is a §3.6 change for the whole app.
