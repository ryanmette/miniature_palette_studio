The scheme library — keeping the schemes you make

Ryan’s answer in the naming study: “save” means schemes, files and links. Today a scheme lives only in its link: close the tab and it is gone unless you kept the link. This study asks where saved schemes live, how Save works when you change a saved scheme, and how a library fits the shopping list, the names and the backup file.

The five schemes on this page are real: scheme.js buildScheme made each one from its paint and harmony, on the full dataset.

Page theme

0One model for all three studies

A saved scheme, a project on the shopping list, and a named link are one thing: a scheme with a name. Think of a folder. The link is the folder’s contents (the paint, the harmony, the pop, the locks). The name is the label on the folder. The to-buy paints are papers that point at the folder. A store swap is a sticky note on one role. The library is the drawer that holds the folders.

A correction to the naming study’s sketch

The naming study keyed a project by a hash of its link. That breaks once you can save and then change a scheme: a new harmony makes a new link, so a new key, and the to-buy paints would lose their folder. A saved scheme needs a key that never changes: a short random id, made the first time the scheme is saved or its paints are added. The link becomes a field that Save updates.

// store.js v2 — one map for saved schemes and shopping-list projects
schemes: {
  s7k2: { name: 'Plague Marine', link: '?p=citadel-base-death-guard-green&h=triadic…',
          saved: true, created: '2026-10-20', changed: '2026-10-27' },   // no pins: role holds (v1.12.0) are in the link (hd)
  q3m9: { name: '', link: '?p=citadel-base-morghast-bone&h=complementary…', saved: false }   // no name (Skip at export): kept only while its paints are on the list
},
want: ['citadel-base-death-guard-green', …],   // still a list of ids, so an older build reads it
wantInfo: { 'citadel-base-death-guard-green': { qty: 2, for: 's7k2' } }   // as built (ryanmette/miniature_palette_studio#54)
  • A name saves for good (Ryan’s answer 3): naming a project at export, or pressing Save, sets saved: true. Only a project you skipped at export stays saved: false: the app keeps it while its paints are on the list, and it leaves when its last paint is bought — unless you name or save it.
  • The backup file carries the whole map, so Restore brings the library back. Delete my shelf and settings… clears it with the rest. The CSV does not carry schemes (it is a list of paints).
  • Size: a saved scheme is about 300 bytes. A thousand of them is about 0.3 MB, well inside what a browser keeps for one site.

2Save in the Studio — and what happens when you change it

A Save button sits on the hero line, the one line that always names your colour. The first Save asks for the name with the naming study’s field (pre-filled with the automatic name, selected). After that the hero shows the name. Change the scheme, and the hero says Changed with Save (update this one) and Save as new — Adobe’s Update, with a way to branch. This frame works.

Why explicit, not autosave

  • The Studio is for exploring (persona Sam): a drag changes the scheme sixty times a second. Autosave would write over a saved scheme with every experiment. With an explicit Save, exploring is free, and the saved one stays as it was until you say so.
  • Undo stays as it is (undo.js): Save is not a step in the undo history; it copies the current state into the library.
  • Changed shows only while the current link differs from the saved link — a plain string compare.
  • Leaving with changes (opening another scheme) does not block with a dialog: the changes stay in the browser’s history and in the undo stack, and the toast says “Plague Marine has changes you did not save · Go back”.

AA third mode: Schemes

A full page of saved schemes. Each row: a colour strip of the four roles at their 60-30-10 weights (paint data, with the metal sheen, §2), the name, and the facts that matter for buying — the harmony, how many paints you own, how many are on the list. Tap a row to open it in the Studio. ⋯ on a row opens the item menu: Open · Rename · Take to the store · Share link · Delete. This frame works.

For

  • One place for all saved work; easy to explain (“Studio makes, Schemes keeps, Shelf owns”).
  • Maps straight onto a tab bar in the iOS app (IOS_APP_PLAN.md): three tabs.
  • Room for the buying facts — “2 to buy” makes the library a way into the shopping list.
  • Projects with no name (skipped at export) show here too, in italics, under the saved ones: one model, one list. A name, given anywhere, moves it up into the saved list for good.

Against

  • Changes the constitution: §3.6 says the header holds only Studio / Shelf + ⋯. Ryan said yes (answer 1); the line changes in the same commit that builds the mode, not before (§10: the constitution describes what ships).
  • Three segments plus ⋯ on a 360px phone: about 300px. It fits, with less room to spare.
  • A page that is empty for a new painter. The empty state must say how to fill it (below).

B · inside the Shelf

  • No header change. But the Shelf is paints you own; schemes are a different thing in the same drawer, and a nested switch is one more level to find.

C · a list in the Studio

  • Fastest way to switch schemes while you work. But an overlay is a poor place to rename, delete, or see what is on the list. A good shortcut, not a home.

D · a group in Browse

  • The smallest change: the seed field already has a Recent group. But a scheme is not a paint, and the Browse grid is built for paints; there is no place to manage them.

Chosen (Ryan, 2026-10-29): A — a Schemes mode between Studio and Shelf (and a CLAUDE.md §3.6 change); an explicit Save on the hero line with Changed · Save · Save as new; one schemes map in store.js with a stable id, shared by the library, the shopping-list projects, the names and the store swaps; deleting a scheme never deletes paints from the list.
