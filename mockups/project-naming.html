Naming a project — when and how the app asks

The shopping-list study gave each to-buy paint a “for” label: the project it is for. Ryan’s answer: the name is asked on export or save, not when a paint is added. This study asks when exactly, what the app suggests, what happens to paints with no project, and how a name is changed later.

Page theme

0The idea that makes it easy: label now, name later

A name is a word for people. The app does not need it to keep the paints apart. When you press “+ Add N to the shopping list” on a Recipe, the app can silently record which scheme the paints came from — the scheme’s share link is already a unique key for it (share.js encodeState). So nothing is lost while a project has no name: it shows an automatic name until you give it a real one. The question “when do we ask?” then only decides when a person is asked for a word, never when the data is kept.

An analogy: a parcel gets a tracking number at the counter (the key). You can write “Mum’s birthday” on it later (the name). The parcel goes to the right place either way.

The data, as a sketch (a store.js version bump)

// today
{ v: 1, owned: ['…'], want: ['citadel-base-mephiston-red', …], prefs: {…} }

// with counts, labels and names
{ v: 2, owned: ['…'],
  want: [{ id: 'citadel-base-mephiston-red', qty: 1, for: 'k7f3' }, …],
  projects: { k7f3: { name: 'Blue knight', scheme: '?p=…&h=triadic…' } },   // no name yet → name: ''
  prefs: {…} }

The key (k7f3) is a short hash of the scheme link. The share link gets the name as one more parameter (&n=Blue%20knight, answer 3); a link with a name, opened on another device, brings the name with it. A paint added by hand on the Shelf has no for. The Back up file and the CSV carry the new fields; an old backup still restores (no for, a count of 1).

1The moments that count as “export or save”

Today the app has no Save button for a scheme: a scheme lives in its link. Ryan’s answer 2: “save” means all three — saved schemes, files and links. So five moments ask (one of them, Save this scheme, does not exist yet); two do not.

1Take to the storeThe new hand-off panel: the link, the QR code, Print, Save as text. The main moment.
2⋯ → Save the shopping listToday’s text file, until the panel replaces it.
3⋯ → Share linkA scheme’s link. It carries the name (Ryan’s answer 3).
4Shelf → Save my shelf (CSV)The “for” column needs a word, or the key is all you see.
5Save this schemeA saved-scheme library (D) — Ryan’s answer 2: wanted. It needs its own study.
—+ Add to the shopping listNot asked (Ryan). The label is kept silently.
—Back up everythingNot asked: a backup keeps the keys and the names as they are.

3Four ways to ask

A · Every exportEach time a list leaves the app, every unnamed project gets a field. Always named; asks again and again if you skip.
B · Once, at the first exportThe first export with an unnamed project asks once, inside the panel, with a suggestion and Skip. Never again for that project.
C · Never blockExport goes at once with automatic names. The names in the panel are editable in place, like a document title.
D · When you keep a schemeA new “Save this scheme” in the Studio asks for the name. A saved-scheme library — a bigger feature.

BOnce, at the first export — the recommended flow

The first time a list with unnamed projects leaves the app, the hand-off panel opens on a short “Name your projects” step. Each field is pre-filled with a suggestion and selected, so typing replaces it and Enter keeps it. Skip uses the automatic names and never asks for those projects again. This frame works: type, Skip, or Continue.

The suggestion, in this order

  1. A name you used before for this scheme (it was renamed, then its paints were bought, then re-added).
  2. The paint and the harmony: “Death Guard Green · triadic”. Always there, always true — the automatic name.
  3. No “recent names” to pick: a project is one scheme (Ryan’s answer 1), so two schemes never share a project.

Rules

  • Skip is one press, and the export still happens. Asking must never block the list from going to the store.
  • Asked once per project. A skipped project keeps its automatic name and is not asked again; rename it later (below).
  • The step shows only the unnamed ones. A list where every project has a name goes straight to the panel.
  • A name another scheme already has is not an overwrite (the Adobe lesson) and not a join (one scheme per project): the hint says “Another scheme is called Plague Marine”, and the app keeps both, the new one as “Plague Marine (2)” unless you change it.
  • The name goes in the scheme’s link (Ryan’s answer 3). The hint under the fields says so once: “The name is part of the link you share.”
  • Accessibility: each field has its own label (“Name for the scheme from Death Guard Green, triadic”); focus starts in the first field; Continue says “2 projects named” in the panel’s live region (§3.5).

4Changing a name later

A name is changed where you see it: the project’s group header on the shopping list. Tap the name, type, Enter (Esc puts it back). The same works for an automatic name, which is how a skipped project gets a real one. This is Google Docs’ title-in-place.

What a rename changes

  • Every paint with that label, at once — the name lives in one place (projects[key].name), not on each paint.
  • A link already sent keeps the old name. The name is in the link (answer 3), and a link is a copy.
  • Clearing the name goes back to the automatic name. The paints stay on the list.
  • When every paint of a project is bought, the group leaves the list, but the name stays with the scheme: re-add its paints, and the name comes back (suggestion 1).

Paints with no project

  • A paint marked by hand on the Shelf has no label. It goes in a last group, “Other paints”, which is never asked for a name.
  • A paint two projects need shows in both groups, with “Also for …” (as in the shopping-list study, C). It is still one pot on the list unless you add a count.

5Why not A, C or D

A · Every export

  • Asks again after a Skip, so Skip means “not now”, and the step comes back on every trip to the store. That is the pattern that makes people stop exporting.
  • B with no “never again” is A. B keeps A’s good part: the first ask.

C · Never block

  • Zero friction, but most lists will carry “Death Guard Green · triadic” for ever: the automatic name is true, but it is not a project.
  • B’s Skip is C, for the painter who wants it. B is C plus one chance.

D · When you keep a scheme

  • Needs a saved-scheme library: a new place to list, open, rename and delete schemes. It is local data, so §1 allows it, but it is a feature of its own.
  • Ryan’s answer 2: wanted. Its Save asks the same question with the same field, and the shopping list reuses that name — a scheme saved with a name is never asked again at export. Nothing in B blocks it; it needs its own study.

6Verdict and questions

A · Every exportNo — nags; B keeps its one good ask.
B · Once, first exportBuild — one ask, a good suggestion, Skip, rename in place.
C · Never blockInside B — it is B’s Skip.
D · Save a schemeWanted · next study — asks with B’s field; B covers the files and links.
Recommendation: label silently on Add; ask once, at the first export, in the hand-off panel, with the field pre-filled and selected and a one-press Skip; rename in place on the list’s group header. One scheme per project; a repeated name gets “(2)”, never an overwrite. The name rides in the share link. A saved-scheme library (D) asks with the same field, and comes next.
